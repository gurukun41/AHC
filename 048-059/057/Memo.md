# AtCoder Heuristic Contest 057

## 問題の概要
> 動き回る原子同士を好きなタイミングで結合させて、分子を作ることができる。 ただし、原子を結合するには距離に応じてエネルギーを消費してしまうので、できるだけ少ないエネルギーで決められた数の分子を作りたい。

0 ≤ x < L = 10^5、0 ≤ y < L = 10^5 からなる2次元平面を考える。ただし、この平面は左右端（x=0 と x=L）、および上下端（y=0 と y=L）がそれぞれつながっており、全体としてトーラス構造となっている。範囲外の座標は、
x および y をそれぞれ L で割った余りに置き換えることで、常に 0 ≤ x,y < L の範囲に正規化される。
この平面上に N 個の点が存在する。t=0 において、i 番目の点（ 0 ≤ i < N ）の初期位置 (x_i ,y_i )（ 0 ≤ x_i ,y_i < L ）と初期速度 (vx_i ,vy_i )（ −100 ≤ vx_i ,vy_i ≤100 ）が入力で与えられる。初期状態では、各点は独立した連結成分を形成している。


各時刻 t=0,1,…,T−1 において、以下の 1. 結合フェーズ と 2. 移動フェーズ の順で交互に処理を行う。 

1. 結合フェーズ

時刻 t において、異なる連結成分に属する 2 つの点を結合することができる。同一時刻に複数の結合を行ってもよい。

点 i の時刻 t における位置を (x_i ,y_i )、点 j の時刻 t における位置を (x_j ,y_j ) としたとき、点 i と点 j を結合する際の 結合コスト D は、以下の距離の式で計算される：
​
D=round( ((min(L−Δx, Δx))^2 + (min(L−Δy, Δy))^2)^(0.5) )

Δx=∣x_i − x_j ∣, Δy=∣y_i − y_j ∣


点を結合すると、運動量保存則に従って連結成分の速度が更新される。結合前の時点において、点 i が速度 (vx_A ,vy_A ) で動く連結成分 A に属し、点 j が速度 (vx_B ,vy_B ) で動く連結成分 B に属しているとする。連結成分 A および連結成分 B に属しているすべての点について、結合後の連結成分の速度 (vx_new ,vy_new ) は以下のように更新される：

(vx_new, vy_new) = (  (|A| * vx_A + |B| * vx_B) / (|A| + |B|), (|A| * vy_A + |B| * vy_B) / (|A| + |B|) )

ここで、∣A∣、∣B∣ はそれぞれ連結成分に含まれる点の数を示す。結合後、その連結成分に属するすべての点は、同じ速度で動くようになる。結合によって点の位置は変化しない。また、同一時刻内での結合の順序は、結合後の位置、結合コスト、および連結成分の速度に影響しない。

座標および速度は小数となることがあるが、計算はすべて倍精度浮動小数（double）で管理される。

2. 移動フェーズ

各連結成分に属するすべての点の位置を同時に更新する。点 i の時刻 t における位置を (x_i ,y_i )、点 i が属する連結成分の速度を (vx_i ,vy_i ) とすると、時刻 t+1 における点 i の位置 (x_i′ ,y_i′ ) は以下のようになる：

(x_i′ ,y_i′ )=((x_i + vx_i )modL,(y_i + vy_i )modL)


時刻 T において、連結成分数が ちょうど M 個、かつ各連結成分のサイズが ちょうど K となるように結合を計画し、結合コスト D の合計を最小化せよ。
### 得点
すべての結合コスト D の合計を D_sum とする。このとき、1 テストケースの得点は以下のように計算される。得点は大きいほど良い。
​
Score=round( 10^6 × log_2( (L×(N−M)) / ( D_sum + 1 )) )

WAとなるのは以下の場合
- 無効な出力を行った場合
- 時刻 T 時点で連結成分数が ちょうど M 個、各連結成分のサイズが ちょうど K でない場合
- すでに同一連結成分に属している点の間で結合が指定された場合


### 入力
```
N T M K L
x_0 y_0 vx_0 vy_0
​x_1 y_1 vx_1 vy_1 
⋮
x_{N−1} y_{N−1} vx_{N−1} vy_{N−1}
```
- 点の総数は N=300 である。
- 総ステップ数は T=1000 である。
- 目標連結成分数は M=10 である。
- 各連結成分の目標サイズは K=30 である。
- 空間の一辺の長さは L=10^5である。
- (x_i, y_i) は点 i の初期位置を表し、 0 ≤ x_i, y_i < L を満たす整数値である。
- (vx_i, vy_i) は点 i の初期速度を表し、 −100 ≤ vx_i, vy_i ≤ 100 を満たす整数値である。


### 出力
ちょうど 
N−M 行を標準出力に出力せよ。各行は以下の 3 つの整数からなり、時刻 t に点 i と点 j を結合することを表す。 出力の順番は任意であるが、処理は時刻 t の昇順で行われる。
```
t i j
```
出力は以下の条件を満たす必要がある。
- 0 ≤ t < T
- 0 ≤ i,j < N かつ i ≠ j

## コードの説明
- Input
  -  入力を受け取る構造体

- Output
    - 出力を管理する構造体
    - pushで結合情報を追加できる
    - 出力がN-M行でなければassertで落ちるようにしている

- Atom
    - 原子を表す構造体
    - 位置、速度を持つ
    - moveで位置を更新できる
    - change_velocityで速度を変更できる

- Cluster
    - 分子を表す構造体
    - aliveフラグで生存状態を管理する
    - 原子の集合、サイズ、速度、Inputを持つ
    - mergeで他のClusterと結合できる(もし不可能ならfalseを返す)
    - moveで所属する原子全ての位置を更新できる
    - distanceで他のClusterとの最小距離を計算できる

- ClusterGroup
    - 最終的に作成するM個の分子グループを管理する構造体
    - 事前にどの原子がどのグループ（分子）に属するかを保持する
    - 目標サイズKに達しているか、原子を追加可能かを判定する

- State
    - シミュレーション全体を管理
    - 時間を進めながら(advance_to)、グループ内の結合判定を行う

## やったこと
1. アルゴリズムの変更（確実な解の生成）
事前グルーピング（Partitioning）の導入
単純な貪欲法では「サイズKの分子がM個」という制約を満たせない場合があったため、方針を変更。
シミュレーション開始前に、全ての原子を ClusterGroup を用いてM個のグループに割り振る処理 (decide_group) を実装。
各グループは初期位置が近い原子を集めるように貪欲法で構成（最初の1つを選び、それに近いものを順次追加）。

2. バグ修正
原子の重複使用の防止
グループ分けの際、used 配列が関数内でローカル定義されていたため、同じ原子が複数のグループで使われるバグがあったのを修正。solve 関数で一元管理し、参照渡しすることで重複を防いだ。
結合条件の適正化
結合判定 can_merge において、マージ後のサイズが目標サイズ K を超えないように制限を適用。

3. シミュレーションの実装

各ステップにおいて、各グループ内で「生存しており、かつ結合可能な（サイズ制限内）」ペアを全探索し、結合を実行。

    main.cpp の K-means によるグルーピングと、aneal.cpp の焼きなまし法を組み合わせて、「グループごとの結合順序とタイミング」を最適化するコードを作成しました。
